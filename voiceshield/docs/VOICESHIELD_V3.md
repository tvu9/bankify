# VoiceShield V3: measured accuracy before model changes

This version **extends** the existing V2 WebRTC voice-calling application with offline evaluation and release gates. It **does not** change `livekit_pella.py`, the PellaV2 checkpoint, audio preprocessing, or the live risk thresholds. The tested CPU setting remains `VOICE_DETECT_DEVICE=cpu` on macOS 14.

## What is implemented

| Command | Purpose |
|---|---|
| `build_manifest.py` | Create a starter label manifest from your existing consented real/fake recordings |
| `evaluate_dataset.py` | Score labeled clips with PellaV2; report clip-level recall, FPR, AUC, Brier, ECE and per-channel breakdown |
| `simulate_telephony.py` | Create offline narrowband, background-noise, real G.711 μ-law, and Opus (16 kbps) variants |
| `benchmark_streaming.py` | Measure queue drops, inference p50/p95, age, and peak RSS in a streaming *simulation* |
| `calibrate_detector.py` | Fit monotonic Platt calibration on **validation scores only**; screen thresholds with a conservative exploratory FPR bound; evaluate once on held-out test |
| `compare_models.py` | Paired comparison of any future candidate's scores on identical test clips |
| `gate_model_upgrade.py` | Refuse to recommend a candidate unless held-out accuracy AND real-time CPU p95 pass conservative comparison gates |
| `fingerprint_model.py` | Record local model and library metadata, with optional SHA-256 of checkpoint |

The ML inference files use the existing PellaV2 adapter and are NOT a new pretrained model. Model weights are never included in Git. The V3 code has no background uploading and does not save raw call audio. Dataset generation explicitly writes new audio files *only* when you run the offline augmentation command.

## Quick start

In the **installed live application** on your Mac:

```bash
cd ~/telephony/livekit-audio-phone
conda activate voiceshield-pella
export VOICE_DETECT_DEVICE=cpu
python -m unittest discover -s tests -p "test_voice_v3*.py" -v
python voice_detector/fingerprint_model.py --hash-weights --out ~/telephony/model_fingerprint.json
python voice_detector/benchmark_streaming.py --mode pella --duration 30 --hop 1 --threads 4 --out ~/telephony/bench_pella_v3.json
```

The benchmark generates a fixed **synthetic sine waveform**, not synthetic spoken words. It measures inference scheduling only—not detection accuracy or actual phone network latency. Run the existing two-phone test separately for real end-to-end latency and false warnings per call-hour. The model's initial load and warm-up are excluded from the 30-second benchmark. Run the worker before starting a call so warm-up finishes first.

## Dataset creation and licensing

First obtain legitimate, consented, labeled recordings with documented permission and commercial licensing as appropriate. **No voice data is bundled with this patch.** For security evaluation, collect multiple speakers, real environments, languages, phone devices, and different AI speech/voice conversion engines. Do not collect other people's calls without appropriate consent and legal review.

Separate recordings by **source recording and person** before evaluation, so related recordings cannot appear on both sides of the validation/test boundary. Prefer held-out AI generator families and unseen channel conditions for additional stress testing. A large file count does not replace speaker/source diversity.

If you already have folders `~/telephony/datasets/val/real`, `val/fake`, `test/real`, `test/fake`:

```bash
python voice_detector/build_manifest.py --real-dir ~/telephony/datasets/val/real --fake-dir ~/telephony/datasets/val/fake --split val --out ~/telephony/val_manifest.csv
python voice_detector/build_manifest.py --real-dir ~/telephony/datasets/test/real --fake-dir ~/telephony/datasets/test/fake --split test --out ~/telephony/test_manifest.csv
```

Open manifests locally and fill in the actual `speaker_id`, `source_id`, `generator_id`, `channel`, and `license`. The bootstrap script only knows filenames and cannot infer speaker identity, recording provenance or redistribution rights. Do **not** claim unseen speakers from autogenerated IDs. Labels are `real` or `fake`; `split` is `train`, `val`, or `test`; `sample_id` and `source_id` are required. The audio `path` may be absolute or relative to the manifest. In-the-Wild, ASVspoof, and other benchmarks each have distinct licenses; check **the exact version's license and usage rights** before commercial training or redistribution.

Validate the manifests without loading the model:

```bash
python voice_detector/evaluate_dataset.py --manifest ~/telephony/val_manifest.csv --split val --check-only
python voice_detector/evaluate_dataset.py --manifest ~/telephony/test_manifest.csv --split test --check-only
```

Evaluate (four-second windows, max 12 per clip by default; silent/short clips are skipped and counted). Save all score CSVs **outside the repository**:

```bash
python voice_detector/evaluate_dataset.py --manifest ~/telephony/val_manifest.csv --split val --out ~/telephony/val_scores.csv
python voice_detector/evaluate_dataset.py --manifest ~/telephony/test_manifest.csv --split test --out ~/telephony/test_scores.csv
```

**Important:** Each row's score is an **average across windows for one clip**. That is not the same as the live worker's rolling `p_fake`. Calibrating clip scores does NOT justify immediately changing live per-window alerts.

## Simulate telephone conditions

```bash
# Requires ffmpeg for genuine codec encoding and decoding.
python voice_detector/simulate_telephony.py --manifest ~/telephony/test_manifest.csv --split test --profiles narrowband,noise10,g711u,opus16 --out-dir ~/telephony/test_telephony_variants
python voice_detector/evaluate_dataset.py --manifest ~/telephony/test_telephony_variants/manifest.csv --split test --out ~/telephony/test_telephony_scores.csv
```

- `narrowband`: fourth-order 300–3400 Hz filtering, 8 kHz resampling, then return to 16 kHz; this is channel **approximation**.
- `noise10`: reproducible additive random noise at approximately 10 dB SNR.
- `g711u`: actual FFmpeg G.711 μ-law encode/decode at 8 kHz with a bandpass filter.
- `opus16`: actual FFmpeg Opus encode/decode at 16 kbps, VoIP mode, using 48 kHz internally.

**Not modeled here:** cellular carrier networks, packet loss, echo cancellation, codec negotiation, conversational turn-taking, network delays. Also record ethically consented LiveKit calls through a separate explicit opt-in test collection if approved. Under no circumstances should private live calls be recorded automatically by the detector.

## Calibrate scores (offline experiment only)

```bash
python voice_detector/calibrate_detector.py \
  --validation-scores ~/telephony/val_scores.csv \
  --test-scores ~/telephony/test_scores.csv \
  --min-per-class 100 --max-fpr 0.05 \
  --out ~/telephony/calibration_review.json
```

Calibration refuses to proceed with fewer than 100 real and 100 fake validation **clips** by default, and requires each validation source ID to be unique. The proposed FPR screen uses a one-sided Wilson upper statistic on validation; since the threshold is selected on that same sample, it **does not provide a statistically certified deployment FPR**. Held-out test results and longer call-level assessment are mandatory. If there is no candidate threshold, the tool records that fact and leaves the live threshold untouched. `calibration_review.json` does not automatically load into the live worker.

**Never tune on the held-out test.** Once a test set has influenced design choices, create another untouched test set. Overlapping four-second windows are correlated; report the false alarms per call-hour and realistic call-level time-to-detect, not just clip-level metrics.

## Compare a future smaller detector or fine-tuned PellaV2

Use identical source IDs and labeled test clips to produce a second CSV with the same columns. Run:

```bash
python voice_detector/compare_models.py --baseline ~/telephony/test_scores.csv --candidate ~/telephony/candidate_test_scores.csv
```

For an objective **release gate**, additionally benchmark both models' real-time CPU p95 on the same Mac, and run `gate_model_upgrade.py`. It requires no worse real-call-relevant false-positive rate, no worse fake recall, at least 0.005 absolute AUC gain, and at least 5% improvement in p95 inference; these are conservative *screening* conditions, not an acceptance certificate. The threshold 0.5 is diagnostic; approved operating points must be selected on validation first. Model replacement remains blocked until signed-off, separate call-level tests.

## When to fine-tune

1. Establish held-out baseline by channel, speaker and known/unseen generator.
2. Determine whether errors come from channel compression, language, model type, or poor threshold calibration.
3. Only then plan frozen-backbone/head-only fine-tuning using a licensed **training** partition; use unseen people, generators and original recordings in validation/test.
4. Keep the original PellaV2 unchanged in production. Publish experimental weights only if usage rights permit, and track their checkpoint hash/version outside Git.
5. Gate promotion on **accuracy + CPU time + sustained RAM + call-level false alerts**. Avoid full W2V-BERT fine-tuning on this Mac until memory and performance are measured.

No weights have been trained in V3 because no user dataset has been supplied. `PellaV2` remains the production baseline and `VOICE_DETECT_DEVICE=cpu` remains the supported local setting. macOS 14 plus your previous MPS crash is not a safe live-GPU environment.

## Performance / operational notes

- Preserve 16 kHz mono and complete **four-second** windows; don't shorten them to game first-result latency.
- Keep LiveKit capture asynchronous from inference and the pending queue max-size 1; work that falls behind gets dropped instead of indefinitely delaying warnings.
- Default live hop is 1 second when CPU keeps up. If p95 inference is close to or exceeds 1 second, compare hop 2 seconds in the same real call benchmark before increasing work rate further.
- Prewarm before calls (`VOICE_PREWARM=1`) and set CPU threads to a measured value; your previous steady-state CPU result was about 981 ms. A faster mock is **not evidence** of better detection.
- Do not present raw sigmoid scores as verified posterior probabilities or automatic identity/transaction approvals. Use independent caller verification for high-risk banking actions.
- Keep secrets, models, recorded audio, manifest paths and score results outside Git. Never publish the Caddy CA key, room signing key, tokens, or customer data.
